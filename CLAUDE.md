# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`wlr-sys` — raw FFI bindings to wlroots 0.17, generated by bindgen at build time.
Published on crates.io. A safe wrapper crate `wlr` is planned as a second
workspace member under `crates/`.

Raw pointers, pervasive `unsafe`, and the absence of safe abstractions are
deliberate and specified. Do not add `Drop` impls, lifetimes, or safety wrappers
here — those belong in `wlr`.

## Commands

```sh
cargo test --workspace                    # everything
cargo test -p wlr-sys --test signal       # one test file
cargo test -p wlr-sys signal_delivers     # one test by name substring
cargo run -p wlr-sys --example headless   # end-to-end: starts a backend, tears it down

cargo clippy --workspace --all-targets    # CI runs this under RUSTFLAGS=-D warnings
cargo doc -p wlr-sys --no-deps            # CI runs this under RUSTDOCFLAGS=-D warnings
```

Requires wlroots 0.17 + headers (`wlroots-0.20.pc`), `libclang`, and the
`wayland-scanner` binary. Arch is currently the only distro packaging wlroots
0.17.

### Feature matrix

Changes to `build.rs` or the blocklists must be checked across configurations —
each exercises a different path, and the default build alone will not catch a
regression in any of them:

```sh
cargo test -p wlr-sys --no-default-features
cargo test -p wlr-sys --no-default-features --features drm-backend      # transitive session.h
cargo test -p wlr-sys --no-default-features --features libinput-backend # optional input-sys
cargo test -p wlr-sys --features vulkan-renderer                        # needs vulkan-headers
cargo test -p wlr-sys --features wayland-sys/dlopen                     # removes wayland-sys's #[link]
```

### Inspecting generated output

There is no committed `bindings.rs` for normal builds. To read what bindgen
actually produced — often the fastest way to answer "is this type/symbol bound?":

```sh
find target/debug/build -maxdepth 3 -name bindings.rs -path '*wlr-sys*' \
  -printf '%T@ %p\n' | sort -rn | head -1 | cut -d' ' -f2-
```

(`ls -t` is unreliable here — some shells alias `ls` to a tool that rejects `-t`.)

Multiple `wlr-sys-*/out` directories accumulate, one per feature configuration,
and stale ones persist. **Always check mtime against `build.rs` before trusting
one.** `wrapper.h` in the same directory lists the headers that were bound;
`../output` holds the emitted cargo directives.

### docs.rs snapshot

`prebuilt/bindings-docsrs.rs` is committed so docs.rs (which has no wlroots) can
build. Regenerate after any change to the bound API — CI diffs it and fails on
drift:

```sh
cargo build -p wlr-sys --all-features
newest=$(find target/debug/build -maxdepth 3 -name bindings.rs -path '*wlr-sys*' \
  -printf '%T@ %p\n' | sort -rn | head -1 | cut -d' ' -f2-)
cp "$newest" crates/wlr-sys/prebuilt/bindings-docsrs.rs
DOCS_RS=1 cargo doc -p wlr-sys --no-deps --all-features   # verify it renders
```

## Architecture

### `build.rs` is most of the crate

Six phases, in order: probe wlroots → read `have_*` capabilities → reconcile
against Cargo features → regenerate vendored protocols → synthesise `wrapper.h`
→ run bindgen. The `SUBSYSTEMS` table drives all of it; adding a wlroots
subsystem means adding a row there, a feature in `Cargo.toml`, and a row in
`crates/wlr-sys/README.md` (kept in the same order deliberately).

Header selection **scans** the installed include tree rather than hardcoding, so
a wlroots patch release that adds a header is picked up automatically. The gated
headers are then subtracted. Because the scan is dynamic and the gate list is
static, `collect_headers` asserts every gated path still exists — otherwise a
renamed header silently becomes unconditional and pulls `<vulkan/vulkan_core.h>`
into machines that lack it.

### Type identity is the load-bearing invariant

Types crossing into other libraries (`wl_display`, `wl_listener`, `xkb_keymap`,
`libinput_device`, …) are **blocklisted** in bindgen and imported from
`wayland-sys` / `xkbcommon-sys` / `input-sys`, so they are the same Rust types
downstream consumers use.

The failure mode is silent. A name missing from a blocklist does not error —
bindgen generates its own definition, the glob import loses to it, everything
compiles, and downstream gets a look-alike type. This is how
`libinput_tablet_tool` shipped wrong once already. Do not trim the blocklists by
grepping `wlr/` headers: several entries are reachable only transitively through
`wayland-server-core.h`.

`tests/interop.rs` is the guard — it coerces real wlroots functions to signatures
written in the ecosystem crates' types, so a re-shadowing becomes a compile
error. Note it can only check *nominal* types; `xkb_*_t` are transparent `= u32`
aliases and are unprovable (and harmless).

pixman, `drmModeModeInfo`, and the libc types are deliberately generated locally,
for reasons documented at their definitions.

### Subsystem detection does not reach downstream via cfg

`cargo::rustc-cfg` applies only to this package's own targets. Downstream crates
receive the reconciliation result as `links` metadata: `DEP_WLROOTS_HAVE_*`.
`emit_subsystem_metadata` publishes both. In-repo tests can use the cfgs directly
and will mislead you about whether the downstream contract works — verify that
against a real dependent crate.

Relatedly, `links = "wlroots"` is deliberately **not** version-suffixed: cargo
enforces one package per `links` value, which is what rejects a graph containing
two `wlr-sys` minors. A suffixed value would permit exactly the ABI collision it
exists to prevent.

### Vendored protocol XML

Two of wlroots' installed headers `#include` generated `wlr-protocols` headers
that wlroots keeps private to its own build, so the public headers cannot be
compiled as shipped. `protocol/*.xml` is vendored and regenerated with
`wayland-scanner` into `OUT_DIR`. Pinned by checksum; CI verifies. See
`protocol/PROVENANCE.md` before touching it.

### Hand-written modules

`src/signal.rs` and `src/list.rs` supply what bindgen cannot: libwayland's
`wl_signal_*` helpers are `static inline` (no linkable symbol), and
`wl_container_of` / `wl_list_for_each_safe` are macros.

The two macros take **different fields**, and it matters:

- `container_of!` is handed a `*mut wl_listener` pointing at the embedded
  listener → field is `listener`.
- `wl_list_for_each!` walks the `link` fields *inside* those listeners → field is
  `listener.link`.

Those offsets coincide only because `wl_listener.link` is declared first;
`tests/signal.rs` pins that dependency.

`wl_list_iter` is C's `wl_list_for_each_safe`, not `wl_list_for_each` — the
cursor advances before yielding, so unlinking the element you were just handed is
supported (destroy handlers do this); disturbing the *next* one is not.

### What each test proves

They are not redundant — each covers something the others structurally cannot:

| File | Covers |
|---|---|
| `tests/interop.rs` | Type *identity* against the ecosystem crates. Layout assertions cannot check this. |
| `tests/subsystems.rs` | When a `wlr_has_*` cfg is set, that subsystem's symbols were actually bound. |
| `tests/link.rs` | The linked `.so` matches the headers bindgen read, down to the patch version; and that the crate version tracks the wlroots version. |
| `tests/signal.rs` | The hand-written `wl_signal` / `wl_list` / `container_of!` code against real libwayland. |
| `examples/headless.rs` | Link-time symbol resolution and end-to-end backend bring-up. |

bindgen's own ~690 `const _` layout assertions run on every build and cover
struct layout; the tests above cover what layout checks cannot.

## Conventions

**MSRV is 1.88** (`rust-version` in the workspace manifest) and it is a published
promise. The host toolchain is newer, so post-1.85 syntax compiles locally and
fails only in the `msrv` CI job. Two things have already gone wrong here:
let-chains (stable in 1.88) slipped past local builds, and a *declared* MSRV of
1.85 turned out to be unachievable for consumers because `bindgen` → `which` →
`home` needs 1.88 — our own CI missed that because the repo has an untracked
`Cargo.lock` and a fresh consumer resolve has none. When changing the MSRV,
verify against a real consumer, not just this workspace. Check with:

```sh
cargo +1.88 check --workspace --all-features
```


`crates/wlr-sys/README.md` **is** the crate's rustdoc (`#![doc = include_str!]`).
Editing it changes published documentation, and a broken link or an untagged code
fence there breaks the doc build.

Comments explaining non-obvious C-side hazards are load-bearing — why a type is
blocklisted, why a header needs a define, why an enum style was chosen. Deleting
them reintroduces real bugs.

Version bumps touch ~8 files and have a known trap (the `range_version` upper
bound is a separate constant on purpose). Follow `docs/RELEASING.md`.

Within a wlroots minor, the hand-written API is **frozen** — `0.20.0 → 0.20.1` is
an automatic upgrade for consumers, so there is no version in which to break
`wl_list_iter`, the macros, the feature names, the cfg names, the
`DEP_WLROOTS_*` keys, or the blocklist. Those wait for the next wlroots minor.

`docs/superpowers/specs/` holds a dated design record. It is **frozen and not
maintained**; several decisions in it were later revised. Where it and the README
disagree, the README is right.
